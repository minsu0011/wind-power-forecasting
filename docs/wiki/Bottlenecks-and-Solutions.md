# 주요 병목과 제외한 접근

## 학습 recipe와 후속 trainer의 단위 불일치

Shared 모델이 개발에서는 capacity factor, 후속에서는 kWh를 사용했습니다. Target과 용량 복원을 동일하게 맞추고 최초·수정 결과를 구분했습니다. 모델 튜닝과 구현 정합성 수정을 섞지 않으려는 선택입니다.

## 정산금 지표와 단순 평균의 차이

고발전 시간의 오류가 더 큰 영향을 주므로 행 수 평균으로 FICR을 계산하면 의도한 목표와 달라집니다. 용량 정규화와 실제 발전량 가중, 6%·8% 경계를 metric 함수에서 따로 확인합니다. Quantile 후보는 이 비대칭을 다루려는 시도입니다.

## 추가 입력이 오히려 나빠지는 경우

SCADA auxiliary의 동일 검증 비교가 기준보다 낮아 기본 recipe에 남기지 않았습니다. 추가 데이터가 있다는 이유만으로 포함하지 않고 시간 가용성과 실제 증분을 봅니다.

## Public feedback을 독립 평가처럼 사용하는 위험

공개 결과를 보고 scale을 고른 뒤 그 점수를 독립 holdout 결과라고 부를 수는 없습니다. Global scale 결과도 피드백 사용 기록으로 분류합니다. 기간·그룹별 숨은 평가 비중을 역산하는 세분화 탐색은 피합니다.

## 날짜 선택만으로 해결되지 않는 cutoff

Previous-day 파일을 고르는 것과 실제 공개시점 이전 파일을 고르는 것은 다릅니다. 원본 run과 publication 정보가 없으면 미래정보 위험이 남습니다. 데이터 확보·추출 성공·모델 개선은 각각 별도 단계입니다.
